# ROBOT templates for bringing the ALI into RadLex

Draft for review. These tables turn release 1.0.1 of the Anatomic Locations Index into input for [ROBOT](https://robot.obolibrary.org/template), to be applied to `RadLex.owl` in [RSNA/RadLex](https://github.com/RSNA/RadLex) (RadLex issues #3 and #15).

They are generated by `scripts/build_radlex_templates.py`; don't edit them by hand. They were built against the branch of RadLex pull request #39, which moves synonyms to `oboInOwl:hasExactSynonym` and definitions to `obo:IAO_0000115`.

## Files

| File | What it is |
|---|---|
| `ali-add.tsv` | ROBOT template. One row per ALI entry, holding everything to add to its RadLex class. 1,880 rows are existing classes and 1,013 are new classes. |
| `ali-remove.tsv` | ROBOT template. Values to take out of RadLex, because a row in `ali-add.tsv` replaces them or because the ALI dropped them. |
| `new-class-ids.tsv` | The provisional RID given to each ALI combined ID, such as `RID7651_RID5824`. |
| `review-notes.tsv` | Rows a reviewer should look at. Not ROBOT input. |

In both templates, row 1 is the column name and row 2 is the ROBOT template string. Columns with an empty row 2 are there for reviewers, and ROBOT ignores them. A `|` separates several values in one cell.

## What the tables do

**New classes** (1,013). Each gets a label, a `RID:RadLexID`, one or more parents, containment, part-whole, synonyms, codes, `RID:Radlex_version_of_class_change` of `4.4 new`, and `RID:Source` of `Anatomic Locations Index 1.0.1`.

- RIDs start at `RID52000`. This is provisional; change it with `--first-rid`.
- The parent is the unsided entry where the ALI has one (876 classes). Otherwise it is the part of the combined ID that names the same kind of structure: "first metatarsal" goes under metatarsal, not great toe (122 classes). A deciduous incisor goes under both incisor tooth and deciduous tooth.
- 15 parents were chosen by hand: the twelve ribs under rib, the cranial cavity under body cavity subdivision, and the supratentorial and infratentorial brain under segment of brain.

**Existing classes** (1,880).

| Area | Added | Removed |
|---|---|---|
| English label | 379 changed | the 379 old labels |
| Synonyms | 1,042 synonyms and 8 acronyms, across new and existing classes | 420 English synonyms that are now the label or that the ALI dropped |
| Definition | 45 reworded | the 45 old definitions |
| Codes | 4,897 `RID:ExternalRefID` values, across new and existing classes | 54 FMA and UMLS codes the ALI corrected |
| `Contained_In` | on every class but the root | 83 that disagree with the ALI, and the 80 matching `Contains` on the old container |
| `Part_Of` | 954 | none |

- Code prefixes are `FMA`, `UMLS`, `SNOMEDCT`, `TA2`, and `MESH`. The last three are new to RadLex.
- `Part_Of` is added only where RadLex doesn't already link the class to the same whole with a part property such as `Regional_Part_Of`. RadLex's own part relations all stay. The 259 classes where the ALI's whole differs from RadLex's are listed in `review-notes.tsv`.
- Eight ALI combined IDs turned out to be existing RadLex classes under another RID, such as `RID13374_RID5824` and `RID43048`. They are treated as the existing class.

## Not included

- `sexSpecific`.
- The 754 SNOMED CT laterality expressions, such as `27175001:272741003=24028007`. Only plain codes are exported.
- Left/right links. RadLex has no laterality relationship; a sided class is a subclass of the unsided one.
- The reverse relationships `Contains` and `Has_Part` on the container or whole.
- `RID:Radlex_version_of_class_change` on changed existing classes, and `created_by` and `creation_date` on new ones.
- German and Latin names, and every RadLex relationship other than `Contained_In` and `Part_Of`, are untouched.

## Rebuilding and applying

```sh
uv run scripts/build_radlex_templates.py --radlex-owl PATH/RadLex.owl --out radlex-import

P='RID: http://www.radlex.org/RID/'
robot template --input RadLex.owl --prefix "$P" --template ali-add.tsv --output add.owl
robot template --input RadLex.owl --prefix "$P" --template ali-remove.tsv --output remove.owl
robot unmerge --input RadLex.owl --input remove.owl merge --input add.owl --output RadLex.new.owl
```

Give `robot template` the `--input`. Without it ROBOT can't tell which RadLex properties are object properties, and it mistypes some rows.

Applied this way with ROBOT 1.9.10, the result passes RadLex's reasoner check and report checks, every ALI value is present, and no class outside the ALI changes except for the removed `Contains`.
